## 问题反馈

### 1、Dialog 样式问题

目前的 Dialog 存在 win11/winui 3 和 win10 fluent style 样式混合的问题。例如 Remote Sever > Delete All Server 或是 Delete 单个 server，弹出的窗口都是 win 10 fluent style（亚克力背景，方形边框无圆角）。请统一到 win11 mica style 的 dialog.

### 2、页面设计问题

目前合格的页面只有 Profile 和 Server 的表单页面。其他页面都存在文字密集堆砌，视觉逻辑混乱，缺失层次感等问题。具体来说

#### Dashboard 页面

功能与说明文本较多，堆积密度大，目前的视觉观感像是专业的系统控制台页面，和我一开始想设计出的简洁大气、现代的 WinUI 3 App 背道而驰。

可以假设使用此 App 的用户都是具有网络、SSH、命令等基础知识的专业用户/程序员。

目前的信息量是足够甚至多余了，考虑直接删除一些说明/提示文字，将一些重要性和优先级较高的说明文本收进二级菜单或者鼠标悬停/点击才弹出的 popup 提示。

考虑将空间规划给功能性控件，以及按一定结构布局页面，制造层次感。

#### 列表

Profiles，Servers 的菜单应添加右键菜单功能（Pin/Unpin，Remove）；

Profiles，Servers 的菜单，可以考虑更加多样的呈现形式（例如 Card + UniformGrid 卡片式）

现有列表样式都太朴素，并且喜欢堆砌文字进行各种属性/状态的详细说明，这样会显得复杂和密集，丢失层次感而不美观。

对现有的每个列表（如 DashboardPage 里的 Active Tunnels, Recent activity，Profiles, Servers 里面的列表等），你可以做以下思考

- 构成列表的每一项（列表项）有哪些元素组成？对应后端数据模型的哪些字段？
- 每个元素，能否先用图标、decoration、背景颜色等等进行标注和区分，是否必须要用文字？
- 如果必须用文字（例如名称、端口号等），那么文字的主次感如何设计？主次文字的样式如何设计，用 WinUI  样式库的 Brush 不要硬编码颜色代码；
- 确定每个组成元素的 UI 形式后，如何布局？哪些元素比较重要，需要占据核心/采用大头，哪些元素是补充说明，可以自动隐藏/贴边对齐/收纳到"More"？
- 最后确定每一项 Container 的样式，普通 ItemsView/ListView 还是 UniformGrid+Card？
- 最后再开始设计 ListView，Container Style，DataTemplate 等。

这里有一个进阶的问题，如果列表项同时包含操作按钮（Start/Stop，Pin/Unpin，Remove）等，那么鼠标悬停到操作按钮上时，会同时显示 ListItem 和按钮本身的 Hover Style，我体感下来觉得会导致焦点不明确，层次感混乱，你也需要认真思考如何解决这个问题（更改 ListView 的 HoverStyle 或者设计特殊的交互逻辑等？）

### 1、设置页

我看了下目前的 SettingsGroup 效果并不好，表现在 Heading 的 Padding 不美观。采用 DevWinUI.Gallery 的方案比较合适，即 TextBlock 作为 Heading 然后用单独的 SettingsCard/SettingsExpander 替代 SettingsGroup，不同 Section 之间用较大 Padding 隔开即可。

### 2、对齐问题

Active Tunnels 的列表项，"Running" 状态指示文字应该垂直居中，右侧三个操作按钮也应该垂直居中，目前都是偏上，请修复。

### 3、Profiles - Add Rule

Profiles 页，Add Rule 操作，现在的做法是在页面下方直接追加表单部分，请改为 popup 或者 dialog 形式，增加层次感，让用户注意力聚焦在表单上。

### 4、侧边栏响应式

侧边栏收缩时，

- 最下方 Settings 图标显示不全，右边有部分被截断；
- Dashboard 页按钮消失；
- "N active" 状态指示器显示不全；

请优化侧边栏的响应式设计

- 增加收缩时的宽度或者调整侧边栏按钮布局，收缩时图标不要被截断；
- 状态指示器增加相应式设计，收缩时简洁显示（例如显示一个数字 1 加一圈装饰），避免文字被截断。

### 5、大幅精简测试流程

现在 UI/UX 处于重构期，各种设计还未稳定，不急着测试 UI/UX 的稳定性，可以先大幅精简测试流程，提高交付效率，这样我们可以快速迭代。等到后期设计元素稳定下来后再慢慢恢复全量测试。
